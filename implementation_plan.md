# WhatAStory-Level Quality Implementation Plan

> Based on frame-by-frame analysis of 6 WhatAStory reference videos (Fronter, Bordio, Qanapi B2B, Screenjar, Viable, Master MG / Pretaa) against MarkyStudio's current 72-skill pipeline.

---

## EXECUTIVE SUMMARY

After analyzing every frame of the 6 WhatAStory reference videos, I identified **12 critical quality gaps** between what they produce and what MarkyStudio currently generates. The gaps fall into 3 tiers:

- **Tier 1 — Cinematic Foundation** (biggest visual impact, needed first)
- **Tier 2 — Scene-Type Expansion** (new scene types WhatAStory uses that we lack)
- **Tier 3 — Polish & Precision** (subtle quality details that separate agency from amateur)

## GAP ANALYSIS — 12 CRITICAL GAPS

### GAP 1: Stock Video Background Compositing (CRITICAL)
**WhatAStory**: Fronter + Viable use REAL stock footage (office environment, person at desk) as background, with motion graphics overlaid on top.
**MarkyStudio**: `VideoPlateMockup` is static image only. Remotion's `<Video>` and `<OffthreadVideo>` components exist in the package but are NOT in compiler scope.
**Impact**: Single biggest visual gap. Stock footage instantly signals "agency produced."

### GAP 2: Extreme Macro Camera Zoom + Selective Focus (CRITICAL)
**WhatAStory**: Bordio zooms 3–5x into specific UI sections. Background elements blur out with selective DOF.
**MarkyStudio**: `CinematicCamera` caps at 1.06x. `DepthBlur` is fixed 6–14px, not focus-distance-aware.
**Impact**: Without macro zooms, all UI scenes feel "pulled back."

### GAP 3: Multi-Screenshot Multi-View Walkthrough (CRITICAL)
**WhatAStory**: Bordio shows 5+ views of same product (table, kanban, calendar, detail panel, chat) with smooth transitions.
**MarkyStudio**: One `imageIndex` per scene → one screenshot per scene. No multi-view sequencing from real screenshots.
**Impact**: Products with multiple views can't be properly showcased.

### GAP 4: Persistent Feature Context Header (HIGH)
**WhatAStory**: Qanapi has "KMS for CSE  Google Workspace" styled header bar above UI during walkthrough.
**MarkyStudio**: `sectionLabel` is plain text top-left. No logo/badge styling.
**Impact**: Viewers don't know WHICH feature they're watching during multi-feature walkthroughs.

### GAP 5: Cinematic Photo Composite with Floating Overlays (HIGH)
**WhatAStory**: Fronter shows real office photo with floating app icons, chat bubbles, and role labels orbiting around it.
**MarkyStudio**: `VideoPlateMockup` can use static photo bg but the "floating icon chaos" pattern doesn't exist as a skill.
**Impact**: The "chaos intro" is WhatAStory's signature opening.

### GAP 6: Word-by-Word Narration-Synced Text Reveal (HIGH)
**WhatAStory**: Qanapi shows words that start gray/transparent and become colored exactly as voiceover speaks them.
**MarkyStudio**: `WORD_TIMINGS` and `useAudioSync` exist but LLM rarely uses progressive word-by-word coloring.
**Impact**: Narration-synced text is one of the most powerful "perceived intelligence" techniques.

### GAP 7: Animated Line-Art SVG Icons with Draw-On (MEDIUM)
**WhatAStory**: Consistent line-art SVG icons (person, plane, clock, shield, target) with `strokeDashoffset` draw-on animation.
**MarkyStudio**: No standardized SVG icon set. LLM invents icons per-scene (inconsistent quality).
**Impact**: Inconsistent icon quality across scenes.

### GAP 8: Notification Card Scatter on Dark Background (MEDIUM)
**WhatAStory**: Pretaa shows 4–6 white notification cards floating on dark navy bg with staggered spring entrance.
**MarkyStudio**: `NotificationToast` is single toast. No dedicated scatter pattern.
**Impact**: Perfect for CRM/workflow/notification-heavy SaaS products.

### GAP 9: Traveling Element Along Path (Paper Plane / Dot) (MEDIUM)
**WhatAStory**: Screenjar has paper plane traveling along dotted bezier path. Pretaa has dot traveling along journey path.
**MarkyStudio**: `DynamicConnectorLine` draws paths but has no traveling element.
**Impact**: Traveling elements guide the eye and create visual continuity.

### GAP 10: In-App Chat / Team Messaging Overlay (MEDIUM)
**WhatAStory**: Bordio shows in-app chat thread with avatars, timestamps, typing indicators, real messages.
**MarkyStudio**: `ChatBubble` is a simple bubble. No threaded messaging panel.
**Impact**: Can't showcase built-in messaging features.

### GAP 11: Concentric Rings / Ripple Emanation (LOW)
**WhatAStory**: Concentric rings expanding outward from central icon with different dash patterns.
**MarkyStudio**: `OrbitRing` is a single ring. No multi-ring concentric emanation.
**Impact**: Minor visual polish for abstract scenes.

### GAP 12: Branded Browser Chrome (LOW)
**WhatAStory**: Viable shows browser frame with brand-colored chrome (magenta title bar).
**MarkyStudio**: Default gray/white browser chrome only.
**Impact**: Small brand identity reinforcement.

#### 1B. Extreme Macro Camera Zoom + Animated Selective Focus
**Files**: `compiler.ts` (new components), `generate/route.ts`, new skill doc

**What to do**:
1. Create `MacroCamera` component in compiler.ts:
   - `zoomLevel`: 2.0–5.0 (how much to magnify)
   - `focusPoint`: `{x: 0-1, y: 0-1}` (normalized center of zoom)
   - `zoomInFrame`: when zoom starts
   - `holdFrames`: how long to hold at max zoom
   - `zoomDuration`: animation duration (20-40f)
   - Uses `transform: scale()` with `transformOrigin` at focus point
   - EaseOutExpo zoom-in (snap), linear drift during hold, EaseInExpo zoom-out (whip)

2. Create `SelectiveFocus` wrapper component:
   - Uses CSS `mask-image: radial-gradient()` to create sharp center / blurred edges
   - `focusX`, `focusY`: where the sharp center is (0-1)
   - `focusRadius`: how much of frame is sharp (0-1, default 0.35)
   - `blurAmount`: how blurry the edges are (6-12px)
   - Renders children twice: sharp (masked) layer on top, blurred full layer behind

3. Register both in compiler scope
4. Create `premium-macro-closeup.md` skill doc
5. Update generate/route.ts SYSTEM_PROMPT with MacroCamera usage rules

**Component design**:
```typescript
const MacroCamera = ({ children, zoomLevel=3, focusPoint={x:0.5,y:0.5},
  zoomInFrame=0, holdFrames=60, zoomDuration=30 }) => {
  const frame = useCurrentFrame();
  const zoomIn = interpolate(frame,
    [zoomInFrame, zoomInFrame + zoomDuration],
    [1, zoomLevel], { extrapolateLeft:'clamp', extrapolateRight:'clamp',
      easing: EASINGS.easeOutCubic });
  const zoomOut = interpolate(frame,
    [zoomInFrame + zoomDuration + holdFrames,
     zoomInFrame + zoomDuration + holdFrames + zoomDuration],
    [zoomLevel, 1], { extrapolateLeft:'clamp', extrapolateRight:'clamp' });
  const zoom = frame < zoomInFrame + zoomDuration + holdFrames ? zoomIn : zoomOut;
  return (
    <AbsoluteFill style={{
      transform: `scale(${zoom})`,
      transformOrigin: `${focusPoint.x*100}% ${focusPoint.y*100}%`,
    }}>{children}</AbsoluteFill>
  );
};
```

**Estimated effort**: Medium
